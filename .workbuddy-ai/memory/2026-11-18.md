## Monitoring / charts real-data fix session

**Symptom:** Monitoring page showed avg download 2907.9 Mbps, upload 740 Mbps, 0 active sessions, empty sessions table. Live router had 3 real hotspot sessions and traffic of ~0.02–0.17 Mbps.

**Root causes:**
1. `/api/sessions` and `/api/dashboard` read only local DB tables `hotspotSession` / `routerMetric` that were never synced from the router.
2. `collectInterfaceTraffic()` tried `/interface/monitor-traffic =interface=` (empty) and `=all` which TRAP on CHR ("input does not match any value of interface"), then fell back to `/interface/print stats` mapping cumulative `rx-byte`/`tx-byte` into `rx-bits-per-second` → ~1000× inflation (886/836 Mbps). Also `=type=ether` is NOT a valid query word here — it traps and leaves the interface list empty.

**Fixes:**
- `src/lib/discovery/collectors.ts` `collectInterfaceTraffic()`: list ALL interfaces via `/interface/print`, filter `type === "ether"` in JS, call `/interface/monitor-traffic =interface=<name> =once=` per interface (real bps). Removed the bytes-as-bps fallback entirely; only accepts rows with actual `*-bits-per-second`. Returns `{ok:false,rows:[],error}` on failure (CollectorResult requires `rows`).
- New `src/lib/live-monitoring.ts` `readLiveMonitoring(routerIds?)`: reads `/ip/hotspot/active/print` + per-interface bps directly from router. Parses uptime → startedAt/durationSec, bytes-in/out → uploadMb/downloadMb, speed from linked package profile. Persists real active sessions into `HotspotSession` (delete+recreate per router). Fallback traffic only trusts discovery cache rows newer than 2 minutes.
- `/api/sessions`: now returns live sessions (`readLiveMonitoring`) with `errors` + `fetchedAt`.
- `/api/dashboard`: one-time purge flag on globalThis clears old inflated `routerMetric` + stale `interface_traffic` cache; then writes one REAL sample per poll and charts from those. `activeSessions` KPI from live count.
- Purged 24 historical inflated rows (>50 Mbps) directly from DB (incl. `unassigned` org ones outside tenant scope) and stale traffic cache.

**Verification (after fresh dev-server restart — required for instrumentation/cached collector):**
- `/api/sessions`: 3 real sessions (48:35:43:AB:A2:BB / 10.0.0.66, B8:3B:CC:B4:68:E8 / 10.0.0.253, 38:4A:80:6A:D2:D6 / 10.0.0.254) with real uptime/data and 1 Mbps profile.
